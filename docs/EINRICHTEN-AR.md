الإنترنت. لا تفترض أنك تعرف شيئاً مسبقاً عن «متغيّرات البيئة» أو «المفاتيح».

النسخة الألمانية في `EINRICHTEN-DE.md`.

> **قبل أن تبدأ:** لن تحتاج أي مفتاح خارجي لتشغيل المنصة أول مرة. الأقسام

## ١. ما هو ملف `.env` أصلاً؟

البرنامج يحتاج معلومات لا يجوز أن تُكتب داخل الكود: كلمة سر قاعدة البيانات،
مفتاح خدمة خارجية، عنوان الموقع. لو كُتبت داخل الكود لصارت جزءاً من المشروع،
وكل من يرى المشروع يراها.

لذلك تُوضع في **ملف نصّي منفصل** اسمه `.env.local`. البرنامج يقرأه عند
التشغيل، وهذا الملف **لا يُرفع أبداً** إلى GitHub (اسمه مذكور في `.gitignore`،
أي «تجاهل هذا الملف»).

**شكله من الداخل** — سطر لكل قيمة، بهذا الشكل بالضبط:

```
اسم_المتغيّر=القيمة
```

بلا مسافات حول علامة `=`، وبلا علامات تنصيص إلا إذا كانت القيمة تحتوي مسافة.
السطر الذي يبدأ بـ`#` هو تعليق ولا يُقرأ.

**لماذا اسمه يبدأ بنقطة؟** الملفات التي تبدأ بنقطة مخفية افتراضياً في أنظمة
Mac وLinux. في Windows تظهر عادةً. إن لم ترها في مستكشف الملفات: View ←
Show ← Hidden items.

## ٢. أنشئ `.env.local` — هذه أول خطوة عملية

### لماذا الملف غير موجود عندك؟

**لأنه يجب ألّا يكون موجوداً.** في المشروع يوجد `.env.example` فقط — وهو
**نموذج**: قائمة بكل المتغيّرات مع شرح لكل واحد، لكن بلا قيم سرّية. هذا
الملف مرفوع على GitHub عمداً ليعرف كل من يستنسخ المشروع ما الذي يحتاجه.

أنت تنسخه إلى `.env.local` وتملأ قيمك أنت. نسختك تبقى على جهازك فقط.

### أين «مجلد المشروع» بالضبط؟

هو المجلد الذي فيه ملف **`package.json`**. هذه علامته المؤكّدة. فيه أيضاً
مجلدات `src` و`docs` و`drizzle`، وفيه `.env.example`.

إن كنت لا تعرف أين هو: افتح VS Code، ثم **File ← Open Folder**، واختر
المجلد الذي استنسخت فيه المشروع. اسم المجلد في شريط العنوان هو مساره.

### كيف تفتح PowerShell في هذا المجلد

**الطريقة الأسهل:** افتح المجلد في مستكشف الملفات (File Explorer)، ثم اضغط
في شريط العنوان أعلى النافذة، اكتب `powershell` واضغط Enter. ستُفتح نافذة
أوامر **داخل هذا المجلد بالضبط**.

**أو من VS Code:** القائمة **Terminal ← New Terminal**. تُفتح تلقائياً في
مجلد المشروع.

**تأكّد أنك في المكان الصحيح** قبل أي أمر:

```powershell
Test-Path package.json
```

إن ردّ `True` فأنت في المجلد الصحيح. إن ردّ `False` فأنت في مكان آخر.

### الأمر — Windows (PowerShell)

```powershell
Copy-Item .env.example .env.local
notepad .env.local
```

السطر الأول يُنشئ الملف، والثاني يفتحه في Notepad جاهزاً للتعديل.

> **لن تجد `.env.local` قبل أن تنفّذ هذا الأمر.** الملف **غير موجود** في
> المشروع أصلاً — وهذا مقصود، لأنه يحتوي أسرارك أنت. ما تراه في المجلد هو
> `.env.example` فقط، وهو النموذج.

### الأمر — Mac أو Linux

```bash
cp .env.example .env.local
```

### تأكّد أنه أُنشئ

```powershell
# Windows
Get-Content .env.local | Select-Object -First 5
```

```bash
# Mac / Linux
head -5 .env.local
```

إن رأيت أسطر التعليق الأولى فالملف موجود. الآن افتحه بأي محرّر نصوص
(Notepad، VS Code، أي شيء) — وستعدّله في القسم التالي.

> **لا تعدّل `.env.example` نفسه.** هو النموذج المشترك؛ تعديله يعني أن
> تعديلك سيُرفع إلى GitHub مع المشروع.

## ٣. المتغيّرات الإلزامية — سطرين فقط

بعد النسخ، الملف يحتوي كل المتغيّرات لكن أغلبها **فارغ**، وهذا صحيح. للتشغيل
الأول تحتاج **اثنين فقط**، وهما مملوءان مسبقاً في النموذج:

```
DATABASE_URL=postgres://postgres@localhost:5433/postgres
PORT=3001
```

| المتغيّر | ماذا يعني بالعربي | إن كان خاطئاً |
|---|---|---|
| `DATABASE_URL` | عنوان قاعدة البيانات: «اتصل بـPostgres على جهازي، المنفذ ٥٤٣٣» | البرنامج لا يبدأ ويقول `ECONNREFUSED` |
| `PORT` | المنفذ الذي تفتح عليه المنصة في المتصفّح (`localhost:3001`) | إن كان مشغولاً: `EADDRINUSE` — غيّره إلى ٣٠٠٢ |

**لا تغيّر شيئاً آخر الآن.** بقية المتغيّرات الفارغة تعني «هذه الوظيفة غير
متصلة»، والمنصة تعمل بدونها وتقول ذلك بصراحة في واجهتها.

### متغيّر ثالث مهم للتجربة

```
CSE_DEV_FLAECHEN=1
```

موجود مسبقاً بقيمة `1`. معناه: **وضع التجربة**. يفعّل ثلاثة أشياء تحتاجها الآن:

- بيانات تجريبية واقعية (شركات، موظفون، عقود، فواتير)
- رمز الدخول (SMS) يظهر **على الشاشة** بدل إرساله فعلياً
- صفحة دخول سريعة `/dev/anmelden`

> **في الإنتاج اتركه فارغاً.** وجود `1` هنا على خادم حقيقي يعني أن أي شخص
> يستطيع الدخول كأي مستخدم.

## ٤. شغّل قاعدة البيانات

المنصة تحتاج Postgres. أسهل طريقة: Docker.

**ثبّت Docker Desktop** من <https://www.docker.com/products/docker-desktop>
ثم شغّله وانتظر حتى تصير الأيقونة خضراء.

ثم في مجلد المشروع:

```powershell
docker run -d --name cse-db -p 5433:5432 -e POSTGRES_HOST_AUTH_METHOD=trust pgvector/pgvector:pg16
```

**لماذا `pgvector/pgvector:pg16` وليس `postgres:16`؟** هو نفس Postgres 16،
لكن معه إضافة `vector` التي يحتاجها فهرس المعرفة. بدونها يتوقّف
`pnpm db:migrate` في المنتصف وتبقى قاعدة البيانات نصف جاهزة.

**تأكّد أنها تعمل:**

```powershell
docker ps
```

يجب أن ترى سطراً فيه `cse-db`.

## ٦. تأكّد أن كل شيء سليم

ثلاث صفحات تقول لك الحقيقة، بلا تخمين:

| الصفحة | ماذا تقول |
|---|---|
| `/healthz` | هل الخادم حيّ أصلاً — يجب أن يردّ `ok` |
| `/portal/<الشركة>/einstellungen/integrationen` | حالة كل ربط خارجي: متصل أم لا، ولماذا |
| `/portal/<الشركة>/einstellungen/jobs` | هل المهام الليلية تعمل فعلاً — **سجلّ تشغيل**، لا نيّة |

صفحة `integrationen` تسأل المحوّلات نفسها، لا قائمة مكتوبة يدوياً. لذلك
لا يمكن أن تتقادم أو تكذب.

**إلى هنا انتهى الإلزامي.** المنصة تعمل بالكامل. كل ما بعده اختياري.

## ٧. القاعدة التي ينبني عليها كل ما بعدها

> **لا شيء يُصطنَع.**

إن غاب مفتاح، تقول المنصة **«غير متصل»** وتواصل العمل بدون تلك الوظيفة. ولا
تتظاهر **أبداً** بأن بريداً أُرسل، أو رسالة SMS وصلت، أو إيصالاً قُرئ.

هذه ليست مجاملة، بل الفرق بين منشأة **تعرف** أنّ عليها إرسال الفاتورة يدوياً،
ومنشأة تبحث عنها في مجلد البريد المزعج.

**أين ترى الحالة الحقيقية — دائماً، بلا تخمين:**

```
/portal/<الشركة>/einstellungen/integrationen
```

هذه الصفحة تسأل المحوّلات نفسها، لا قائمة ثانية. فلا يمكن أن تتقادم.

## ٨. أين يوضع المفتاح — وأين لا يوضع

| | أين | كيف |
|---|---|---|
| **على جهازك** | ملف `.env.local` في مجلد المشروع | انسخ `.env.example`، أعد تسميته، واملأه |
| **في الإنتاج (Vercel)** | Vercel ← Project ← Settings ← **Environment Variables** | أدخل الاسم والقيمة، اختر البيئة، ثم **أعد النشر** |

**ثلاثة أشياء ممنوعة تماماً:**

1. **لا مفتاح داخل الكود.** لا في ملف `.ts`، ولا في تعليق، ولا «للتجربة فقط».
2. **لا مفتاح في commit.** ملف `.env.local` مذكور في `.gitignore` ويجب أن يبقى
   هناك. المفتاح الذي رُفع مرة صار علنياً — حتى لو حذفت الـcommit لاحقاً.
3. **لا مفتاح تسبقه `NEXT_PUBLIC_`.** هذه البادئة ترسل القيمة إلى المتصفّح.
   وضع مفتاح `service_role` الخاص بـSupabase هناك يعني **صلاحية كاملة على كل
   البيانات، لكل زائر**.

**بعد كل تعديل في Vercel يجب إعادة النشر.** المتغيّرات تُقرأ عند البناء، لا
عند الفتح.

## ٩. مفتاح الذكاء الاصطناعي

هنا المنصة **أشدّ من المعتاد**، وعن قصد: أي استدعاء للنموذج يرسل نصوص عقود
ومبالغ وأسماء إلى مزوّد خارجي. لذلك هناك **أربع بوّابات، بالإضافة إلى سطر في
قاعدة البيانات**. إن سقطت واحدة، تقول الواجهة «وظيفة الذكاء الاصطناعي غير
متاحة» ويستمر العمل يدوياً. **ولا يوجد أي مسار التفافي صامت** — لا رجوع إلى
منطقة أخرى، ولا نموذج بديل، ولا طابور انتظار.

الأربعة كلها في `src/server/versand/modell-openai.ts`.

### الخطوة ١ — احصل على المفتاح

1. <https://platform.openai.com> ← سجّل الدخول
2. **Settings ← Organization ← Data controls** ← اضبط **Data residency: EU**.
   بدون ذلك تكون الخطوة ٣ أدناه كذبة.
3. **API keys** ← *Create new secret key* ← انسخه
   (يُعرَض **مرة واحدة فقط**)
4. أبرم **عقد معالجة بيانات (DPA)** — عند OpenAI تحت
   *Settings ← Organization ← Data controls*. بدون DPA لا يجوز أن يخرج عبر
   المنصة أي نص يتضمّن بيانات شخصية (المادة ٢٨ من اللائحة الأوروبية GDPR).

### الخطوة ٢ — أين تضع هذه المتغيّرات بالضبط

**الجواب القصير: هي موجودة عندك أصلاً.** حين نسخت `.env.example` إلى
`.env.local` في القسم ٢، نُسخت معها هذه الأسطر — **فارغة**. أنت لا تضيفها،
أنت **تملأها**.

افتح `.env.local` بأي محرّر نصوص وابحث عن القسم رقم ٤ فيه. ستجد هذا:

```
# --- 4. SPRACHMODELL (OpenAI) ----------------------------------------------
OPENAI_API_KEY=
OPENAI_BASE_URL=https://eu.api.openai.com/v1
OPENAI_DATA_RESIDENCY=eu
OPENAI_EU_HOSTS=
CSE_KI_MODELL=nicht_verbunden
```

**عدّل سطرين فقط:**

| السطر | قبل | بعد |
|---|---|---|
| المفتاح | `OPENAI_API_KEY=` | `OPENAI_API_KEY=sk-proj-abc123...` ← الصق مفتاحك بعد `=` مباشرة |
| المزلاج | `CSE_KI_MODELL=nicht_verbunden` | `CSE_KI_MODELL=` ← **احذف الكلمة**، اترك السطر فارغاً بعد `=` |

**السطران الآخران صحيحان مسبقاً** — `OPENAI_BASE_URL` و
`OPENAI_DATA_RESIDENCY` مملوءان في النموذج بالقيم الصحيحة. لا تلمسهما.

و`OPENAI_EU_HOSTS` اتركه فارغاً — لا تحتاجه إلا في حالة نادرة مشروحة تحت.

**بعد الحفظ:** أوقف الخادم (`Ctrl+C` في الطرفية) وشغّله من جديد
(`pnpm dev`). الملف يُقرأ عند البدء فقط.

> **خطأ شائع:** كتابة علامات تنصيص حول المفتاح. اكتبه عارياً:
> `OPENAI_API_KEY=sk-proj-abc` وليس `OPENAI_API_KEY="sk-proj-abc"`.

**ماذا يفعل كل واحد — والبوّابات الأربع:**

| البوابة | المتغيّر | إن سقطت |
|---|---|---|
| ١ | `CSE_KI_MODELL` يجب ألّا يساوي `nicht_verbunden` | المزلاج الخاص ببيئات الاختبار. **يتغلّب على كل ما عداه** — حتى على مفتاح صالح. هذا أكثر ما يُنسى. |
| ٢ | `OPENAI_API_KEY` | بلا مفتاح: `NOT_CONNECTED`. ولا تُجرى **أي** محاولة. |
| ٣ | `OPENAI_DATA_RESIDENCY=eu` | وإلا `RESIDENCY_BLOCKED`. المحوّل لا يعمل ما لم تُؤكَّد المنطقة. |
| ٤ | `OPENAI_BASE_URL` | يُفحص **مُفكَّكاً**: `https`، ومضيف من القائمة المسموحة، **بلا** بيانات اعتماد في العنوان، **وبلا** query. |

عن البوابة ٤: المسموح افتراضياً هو `eu.api.openai.com` فقط. إن لم يكفِ، أضف
غيره **صراحةً**:

```
OPENAI_EU_HOSTS=endpoint-1.example.com,endpoint-2.example.com
```

> **لماذا قائمة وليس فحص منطقي؟** استدعاء محجوب بسبب خطأ مطبعي أمر مزعج. أمّا
> صفحة عقد تصل إلى مضيف عشوائي لأنّ `OPENAI_BASE_URL` ضُبط خطأً، فهي **واقعة
> واجبة الإبلاغ**.
>
> أيّ نقاط النهاية يغطّيها عقدك — يعرفه عقدك، لا البرنامج. هذا هو السؤال
> المفتوح **O-509**.

### الخطوة ٣ — سجّل النموذج في المنصة

**هذه الخطوة هي التي تُنسى دائماً، وبدونها لا يعمل شيء رغم أن المفتاح صحيح.**

#### أولاً: ما هذا أصلاً؟

المفتاح في الخطوة ٢ يفتح **الباب** التقني. لكن المنصة تسأل سؤالاً ثانياً قبل
أن ترسل أي نص إلى مزوّد خارجي:

> «هل نظر **إنسان** في هذا النموذج وشهد أنه قانوني؟»

الجواب يُخزَّن في جدول اسمه `modell_register` — «سجلّ النماذج». هو قائمة
بالنماذج **المصرّح** باستعمالها، وفيها ثلاث شهادات يجب أن تكون كلها «نعم»:

| الشهادة | بالعربي | من أين تعرفها |
|---|---|---|
| `eu_verarbeitung` | المعالجة تتم داخل الاتحاد الأوروبي | من إعداد **Data residency: EU** في حسابك + عقدك |
| `zero_retention` | المزوّد لا يحتفظ بالنصوص | من شروط OpenAI / عقدك |
| `freigegeben` | أنت شخصياً صرّحت بالاستعمال | قرارك أنت |

**لماذا ثلاث وليس واحدة؟** لأن مزوّداً قد يعالج في أوروبا ولا يضمن عدم
الاحتفاظ. شهادة واحدة مجمّعة كانت ستُخفي **ماذا** فُحص بالضبط.

**ولماذا لا تكفي المتغيّرات؟** لأن المتغيّر إعدادٌ تقني يضبطه من يملك
الخادم. أمّا هذا السطر فهو **إقرار** — فيه اسمك وتاريخ الفحص ورابط عقدك.
عند تدقيق قانوني، هذا ما يُقرأ.

>

> /portal/<الشركة>/einstellungen/modelle
> ```
>
> واملأ النموذج. الصفحة تكتب السطر نيابةً عنك وتضع اسمك تلقائياً في خانة
> «من فحص». هذه هي الطريقة المقصودة.

#### ثالثاً: أو بـSQL مباشرة — إن كنت تفضّل

**ما هو SQL؟** لغة أوامر قاعدة البيانات. السطر `insert into ...` معناه
حرفياً: «أضِف صفاً جديداً إلى الجدول الفلاني بهذه القيم». لا أكثر.

**أين تكتبه؟** إحدى هاتين:

- **Supabase:** افتح مشروعك ← **SQL Editor** في القائمة اليسرى ← **New query**
  ← الصق النص ← **Run**.
- **محلياً على جهازك:**
  ```powershell
  docker exec -i cse-db psql -U postgres -d postgres
  ```
  ثم الصق النص واضغط Enter.

**النص** — غيّر ما بين علامتَي `'` فقط:

```sql
insert into modell_register
  (anbieter, modell, faehigkeit,
   eu_verarbeitung, zero_retention, freigegeben,
   geprueft_am, nachweis_url, bemerkung)
values
  ('openai', 'gpt-4o-mini', 'text',
   true, true, true,
   now(),
   'https://…/dpa.pdf',
   'DPA بتاريخ ٢٠٢٦/٠٩/٢٢، معالجة أوروبية مؤكَّدة، عدم الاحتفاظ مضمون');
```

**كل سطر بالعربي:**

| الجزء | معناه | ماذا تكتب |
|---|---|---|
| `insert into modell_register` | «أضِف صفاً إلى سجلّ النماذج» | كما هو |
| `(anbieter, modell, ...)` | أسماء الخانات بالترتيب | كما هي |
| `'openai'` | المزوّد | `'openai'` |
| `'gpt-4o-mini'` | اسم النموذج | اسم النموذج الذي ستستعمله |
| `'text'` | نوع القدرة | `'text'` للنصوص |
| `true, true, true` | الشهادات الثلاث بالترتيب أعلاه | `true` ثلاث مرات — **إن كانت صحيحة فعلاً** |
| `now()` | تاريخ الفحص = الآن | كما هو |
| `'https://…/dpa.pdf'` | رابط عقدك كإثبات | رابط ملف عقدك، أو احذف السطر |
| `'DPA بتاريخ…'` | ملاحظتك للتوثيق | بأي صياغة تريد |

> **الشهادات الثلاث يجب أن تكون صحيحة فعلاً.** كتابة `true` في
> `eu_verarbeitung` بلا إعداد المنطقة فعلياً ليست ضبطاً، بل **بيان كاذب في
> سجلّ يُقرأ عند التدقيق**. القيد `mr_fremder_anbieter_braucht_menschen` في
> قاعدة البيانات يرفض أصلاً أي تصريح لمزوّد خارجي بلا إنسان مسمّى.

### الخطوة ٤ — تحقّق

```
/portal/<الشركة>/einstellungen/integrationen
```

يجب أن يظهر سطر **Sprachmodell** بحالة `verbunden`. وإن بقي `nicht verbunden`،
فالملاحظة بجانبه تقول **أيّ بوابة** ما زالت مغلقة.

### ما لا يحقّ للذكاء الاصطناعي فعله — مهما كان المفتاح

> **الذكاء الاصطناعي لا يحسب مالاً ولا كميات ولا مواعيد نهائية** (القاعدة
> الثابتة ٦). هو يقرأ، ويستخرج، ويصنّف، ويصوغ مسوّدات. كل رقم يمرّ عبر دالة
> مُختبَرة في `src/server/services/`.
>
> **لا شيء يغادر المنصة بلا موافقة بشرية** (القاعدة الثابتة ٧). البريد،
> العروض، الطلبات، المنشورات — كلها تمرّ عبر `src/server/agent/policy.ts`.

هاتان القاعدتان **لا تتعلّقان** بالمفتاح. تبقيان سارِيتين حتى مع ربط مثالي.

## ١٠. بقية الروابط الخارجية

### ٥.١ تتصل فور ضبط المفتاح

| الربط | المتغيّرات | من أين | بدونه |
|---|---|---|---|
| **Supabase Storage** | `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | Supabase ← Settings ← API | لا يمكن رفع أي مستند ولا استرجاعه — على **جهاز العرض** فقط يتولى `CSE_SPEICHER_ORDNER` ذلك (مجلد على هذا الجهاز، فقط مع `CSE_DEV_FLAECHEN=1`، وأبداً ليس على Vercel؛ D-623) |
| **المهام الليلية** | `JOB_TOKEN` | أنشئه بنفسك: `openssl rand -base64 32`، وضع القيمة نفسها في Supabase ← Database ← **Cron** | لا يعمل أي حارس: لا تحذير نقص تغطية، ولا تحذير انتهاء صلاحية، ولا مقترحات إنذار |
| **الطقس (DWD)** | `DWD_OPENDATA_BASE` | مجاني، **بلا تسجيل** — <https://opendata.dwd.de> | يبقى دفتر البناء اليومي بلا سطر الطقس (VOB/B) |

عن `JOB_TOKEN`: ضبطه يعني **«الباب مفتوح»**، لا «أحدٌ طرَق». ولذلك تعرضه
المنصة بحالة `unbestätigt` حتى يجري تشغيل حقيقي — تراه في
`/portal/<الشركة>/einstellungen/jobs`.

### ٥.٢ تنتظر **قراراً** لا مفتاحاً

هذه الواجهات **مبنية بالكامل**. الناقص هو جواب سؤال لا تستطيع الإجابة عنه إلا
أنت — وهو مدوّن في `docs/DECISIONS.md` تحت «Offen».

| الربط | السؤال المفتوح | ما الذي يجب أن يُقرَّر |
|---|---|---|
| **إرسال البريد** | `O-36` | أي مزوّد **مستضاف في الاتحاد الأوروبي**، وبأي عقد DPA؟ (مثل Brevo، Mailjet EU، أو SMTP خاص) |
| **بوابة SMS** | `O-82` | أي بوابة **مستضافة في الاتحاد الأوروبي** لرمز دخول الموظفين؟ |
| **قراءة الإيصالات (OCR)** | `O-135` | أي مزوّد يقرأ فواتير الموردين؟ |
| **الخرائط وتحديد المواقع** | `O-132` | أي خدمة خرائط مستضافة أوروبياً، وبأي عقد؟ |
| **n8n** | `O-123` | نسخة خاصة أم سحابية؟ |
| **LinkedIn، Instagram** | — | حسابات الشركة وتسجيل التطبيق غير موجودة |

ما دام السؤال مفتوحاً، يبقى السطر `nicht verbunden` **ورقم السؤال بجانبه**.
هذا ليس نقصاً نسيه أحد، بل سؤال لم يُجب عنه أحد.

### ٥.٣ لا ربط، **عن قرار**

| | لماذا |
|---|---|
| **DATEV** | المحاسب القانوني يتسلّم **ملفاً** (D-06). المنصة تُجهّز وتُصدّر وتسلّم؛ لا تُرحِّل القيود. |
| **منصات المناقصات** | **لا توجد API**. التقديم يدويّ عن قصد، لا عن نسيان. |
| **مواقع التوظيف (Indeed، StepStone)** | سحب البيانات يخالف شروط استخدامها ويخلق مخاطرة GDPR. التوظيف يجري عبر الطلبات **الواردة**. |
| **مراسلة شركات لم تطلب شيئاً** | **§ 7 UWG** يمنع الإعلان الإلكتروني غير المطلوب بلا موافقة صريحة مسبقة — **حتى بين الشركات**. الرسائل الصادرة تذهب فقط إلى جهات لها **أساس قانوني مسجَّل**. |

هذه الأربعة مثبّتة في `CLAUDE.md` تحت «Out of scope». من يريد فتحها يغيّر
**قراراً**، لا إعداداً.

## ١٢. التسليم إلى مشترٍ

1. **أنشئ كل المفاتيح من جديد.** المفتاح الذي يعرفه طرفان لا يملكه أحد.
2. **لا تسلّم `.env.local`.** سلّم `.env.example` — القائمة بلا القيم.
3. انقل مؤسسة Supabase، أو أنشئ مشروعاً جديداً **في فرانكفورت** ورحّل البيانات.
4. أبرم عقود DPA من جديد. هي على اسم المشغّل، لا على اسم البرنامج.
5. راجع مع المشتري `docs/DECISIONS.md` قسم «Offen» — هناك ما لم يقرّره أحد بعد.
6. **أعد ضبط حساب السوبر-أدمن.** لا ينشأ إلا عبر البيئة (D-617)، لا عبر أي شاشة.

## ١٣. تسجيل الدخول — أي صفحة لأي غرض

هناك **اثنتا عشرة** صفحة تحت `/auth`، وهي **ليست مؤقتة**: هما **مدخلان** وعشر
**خطوات** ضمن المسارات نفسها. كلها مدوّنة في
`docs/architecture/04-SEITENKARTE.md` §11.

### المدخلان

| | لمن | لماذا منفصلان |
|---|---|---|
| `/auth/login` | الإدارة، القيادة، **العملاء** | بريد إلكتروني وكلمة مرور |
| `/auth/mitarbeiter` | **الموظفون** | **بلا كلمة مرور** — رقم جوال ورمز لمرة واحدة (EMP-01) |

**لماذا للموظفين مدخل خاص.** يقول EMP-01 حرفياً: «رقم هاتف + رمز SMS، **بلا
كلمة مرور**». عاملة النظافة الواقفة في بيت الدرج الساعة ٥:٣٠ ليس لديها مدير
كلمات مرور. لذلك **لا يوجد إطلاقاً** حقل كلمة مرور في `/auth/mitarbeiter` — لا
مخفيّاً ولا معطّلاً، بل غير موجود. الاختبار
`tests/e2e/anmeldung.spec.ts` يَعُدّ عناصر `input[type=password]` ويشترط
أن تكون **صفراً**.

والصفحتان **تُحيلان إلى بعضهما**: من يقف على `/auth/login` ولا كلمة مرور لديه،
يجد في الأسفل جملة «هل تعمل في الميدان ولا تملك كلمة مرور؟» مع الطريق إلى هناك.

### ماذا يفعل زرّ «Login» على الموقع

يذهب إلى **`/auth/login`** (`src/app/(public)/layout.tsx:65`).

> سابقاً كان يشير إلى `/auth/mitarbeiter` لأنه كان المدخل الوحيد المبني — فكان
> الإداريون والقيادة والعملاء يصلون إلى نموذج يسأل عن رقم جوال. منذ PR 77 صار
> العكس.

### إلى أين تصل بعد الدخول

| الدور | أول صفحة | لماذا |
|---|---|---|
| الإدارة، القيادة | `/auth/bereich` | الحساب الداخلي قد يدير عدّة شركات. فهو **يختار** أيّها — ولا شيء مُختار سلفاً (§4.4) |
| الموظفون | `/portal/mein` | إنسان واحد، شاشة عمل واحدة |
| العميل | `/portal/kunde` | ملفّاته هو فقط |

محدَّد في `src/server/auth/zugang.ts:62` (`PORTAL_START`).

**لماذا لا تصل الإدارة إلى «/portal».** هذا العنوان غير موجود في أي سطر من
خريطة الصفحات؛ فتكون وجهة التحويل نفسها خطأ 404. الإدارة ليس لها جذر ثابت
**لأن الشركة جزء من المسار** (`/portal/reinigung/…`).

### الصفحات العشر الباقية — خطوات لا مداخل

| الصفحة | متى تظهر |
|---|---|
| `/auth/zwei-faktor/pruefen` | بعد كلمة المرور، إن كان الدور يتطلّب تحقّقاً ثنائياً |
| `/auth/zwei-faktor/einrichten` | أول مرة، **إلزامياً** قبل أي شيء آخر |
| `/auth/zwei-faktor/wiederherstellung` | فقدان الهاتف ← رمز الاستعادة |
| `/auth/mitarbeiter/code` | رمز الـSMS لمرة واحدة |
| `/auth/passwort-vergessen` | طلب رابط |
| `/auth/passwort-neu` | كلمة مرور جديدة بالرمز الوارد في البريد |
| `/auth/kennwort-wechseln` | التغيير **الإلزامي**، مرتبط بالجلسة، بلا رمز (AUT-07) |
| `/auth/einladung/[token]` | حساب مدعوّ يقبل الدعوة |
| `/auth/bereich` | اختيار الشركة (انظر أعلاه) |
| `/auth/kein-zugriff` | مسجَّل الدخول، لكن **الصلاحية** ناقصة |

**عن `/auth/kein-zugriff`:** لأي **سجلّ** لا يخصّك تردّ المنصة بـ404 — لأن
مجرّد وجوده معلومة (AUT-06). أمّا **الصلاحية** الناقصة داخل شركتك فلا ينطبق
عليها ذلك: وجود الوحدة مكتوب في القائمة أصلاً. من لا يحقّ له، يجب أن يعرف أنه
لا يحقّ له — **وبمن يتّصل**.

### وماذا عن `/dev/anmelden`؟

صفحة الدخول التطويرية: تختار حساباً من قائمة، **بلا كلمة مرور**، وبلا أي فحص.
لا تظهر **إلا** إذا كان `CSE_DEV_FLAECHEN=1`.

> **في الإنتاج يجب ألّا يكون هذا المتغيّر مضبوطاً.** وإلا فالباب الرئيسي مفتوح.

### هل يبقى الوضع هكذا؟

**نعم.** المدخلان قرار لا مرحلة مؤقتة: حساب له كلمة مرور، وحساب ليس له ولا يجب
أن تكون له.

ما **قد يتغيّر** هو تسهيل: صفحة بداية مشتركة فيها خياران كبيران («لديّ كلمة
مرور» / «أعمل في الميدان»). وهذا **صفحة إضافية**، لا إعادة بناء — النموذجان
خلفها يبقيان، لأنهما يفحصان أشياء مختلفة. واليوم تؤدّي `/auth/login` الغرض
نفسه بجملة في أسفلها.

## ١٤. حين لا يعمل شيء — رسائل الخطأ ومعناها

الجدول يقرأ **رسالة الخطأ كما تظهر لك** ويقول ما تفعله. لا تحتاج أن تفهم
الرسالة نفسها.

### عند التشغيل

| الرسالة التي تراها | ماذا تعني فعلاً | ماذا تفعل |
|---|---|---|
| `ECONNREFUSED ... 5433` | قاعدة البيانات غير مُشغّلة | شغّل Docker Desktop، ثم `docker start cse-db` |
| `EADDRINUSE ... 3001` | المنفذ مشغول ببرنامج آخر (أو بخادم سابق لم يُغلق) | غيّر `PORT=3002` في `.env.local`، أو أغلق الخادم القديم |
| `Cannot find module` | الحزم غير مُنزّلة | `pnpm install` |
| `extension "vector" is not available` | استخدمت صورة `postgres:16` بدل `pgvector/pgvector:pg16` | احذف الحاوية وأنشئها من الصورة الصحيحة (القسم ٤) |
| `relation "..." does not exist` | الجداول غير مُنشأة، أو الترحيل توقّف في المنتصف | `pnpm db:migrate` — واقرأ آخر سطر إن توقّف |
| الصفحة بيضاء ولا خطأ | الخادم لم يبدأ بعد | انتظر حتى تظهر `Ready in ...` في الطرفية |

### عند الدخول

| الحالة | السبب الغالب | الحل |
|---|---|---|
| كلمة السر لا تُقبل | البيانات التجريبية غير مُحمّلة | `pnpm db:seed` |
| لا يصلني رمز SMS | هذا صحيح — لا يوجد مزوّد SMS متصل (O-82) | في وضع التجربة الرمز يظهر **على الشاشة** |
| «غير مصرّح» بعد الدخول | الحساب ليس له دور في هذه الشركة | جرّب حساباً آخر — القسم ١٣ |

### عند ربط خدمة خارجية

**القاعدة الذهبية:** لا تخمّن أبداً. افتح:

```
/portal/<الشركة>/einstellungen/integrationen
```

هذه الصفحة **تسأل المحوّل نفسه** وتقول لك السبب بالنص — مثلاً
`RESIDENCY_BLOCKED` أو `NOT_CONNECTED`. ابحث عن السبب في القسم ٩ أو ١٠.

هذه هي الأسباب الستة التي يعرفها المحوّل — لا غيرها:

| السبب المعروض | معناه بالضبط | الحل |
|---|---|---|
| `NOT_CONNECTED` | **إمّا** المفتاح فارغ، **وإمّا** المزلاج `CSE_KI_MODELL=nicht_verbunden` لا يزال مضبوطاً | تحقّق من الاثنين: `OPENAI_API_KEY` غير فارغ، و`CSE_KI_MODELL` لا يساوي `nicht_verbunden` |
| `RESIDENCY_BLOCKED` | مشكلة في المنطقة أو في العنوان: `OPENAI_DATA_RESIDENCY` ليس `eu`، أو `OPENAI_BASE_URL` فارغ/ليس https/فيه بيانات اعتماد/فيه query/مضيفه خارج القائمة المسموحة | اضبط `OPENAI_DATA_RESIDENCY=eu` وأعِد `OPENAI_BASE_URL` إلى `https://eu.api.openai.com/v1` |
| `AUTH_FAILED` | المفتاح موجود لكن OpenAI رفضه | المفتاح خاطئ أو مُلغى — أنشئ واحداً جديداً |
| `RATE_LIMITED` | تجاوزت حدّ الاستدعاءات عند OpenAI | انتظر، أو ارفع الحدّ في حسابك |
| `TIMEOUT` | لم يردّ المزوّد في الوقت المتاح | غالباً مؤقّت — أعد المحاولة |
| `INVALID_RESPONSE` | ردَّ المزوّد بشيء غير متوقَّع | يُسجَّل ولا يُستخدم — لا تُبنى عليه أي قيمة |

> **انتبه:** `NOT_CONNECTED` و`RESIDENCY_BLOCKED` يغطّي كلٌّ منهما أكثر من
> سبب واحد. المزلاج `CSE_KI_MODELL` هو أكثر ما يُنسى: حتى لو كان المفتاح
> صحيحاً تماماً، وجودُ `nicht_verbunden` فيه يوقف كل شيء. **يتغلّب على كل
> ما عداه — وهذا مقصود.**

### بعد أي تعديل في `.env.local`

**أعد تشغيل الخادم.** الملف يُقرأ عند البدء فقط. أوقف بـ`Ctrl+C` ثم
`pnpm dev` من جديد.

وفي Vercel: **أعد النشر** (Redeploy). المتغيّرات تُقرأ عند البناء.

## ١٥. جدول مرجعي — كل متغيّر في سطر

| المتغيّر | إلزامي؟ | من أين تحصل عليه | إن كان فارغاً |
|---|---|---|---|
| `DATABASE_URL` | **نعم** | جاهز في النموذج لـDocker محلياً | البرنامج لا يبدأ |
| `PORT` | **نعم** | جاهز (`3001`) | البرنامج لا يبدأ |
| `CSE_DEV_FLAECHEN` | للتجربة | اكتب `1` | لا بيانات تجريبية، ولا دخول سريع |
| `SUPABASE_URL` | للتخزين | Supabase ← Project Settings ← API | لا رفع مستندات ولا إيصالات |
| `SUPABASE_SERVICE_ROLE_KEY` | للتخزين | نفس الصفحة — **صلاحية كاملة، احذر** | نفس ما سبق |
| `OPENAI_API_KEY` | للذكاء الاصطناعي | platform.openai.com ← API keys | كل وظائف الذكاء الاصطناعي معطّلة |
| `OPENAI_BASE_URL` | مع المفتاح | جاهز (`https://eu.api.openai.com/v1`) | يُرفض الاتصال |
| `OPENAI_DATA_RESIDENCY` | مع المفتاح | اكتب `eu` | يُرفض الاتصال |
| `CSE_KI_MODELL` | مع المفتاح | **احذف** `nicht_verbunden` | المزلاج يمنع كل شيء |
| `OPENAI_EU_HOSTS` | نادراً | فقط إن غطّى عقدك نقاط نهاية أخرى | يُسمح بـ`eu.api.openai.com` فقط |
| `JOB_TOKEN` | للمهام الليلية | أنشئه: `openssl rand -base64 32` | المهام الليلية لا تعمل |
| `DWD_OPENDATA_BASE` | للطقس | مجاني بلا تسجيل — عنوان DWD | دفتر البناء بلا سطر الطقس |
| `CSE_IP_PFEFFER` | للأمان | أنشئه: `openssl rand -hex 32` | تجزئة الـIP قابلة للعكس |
| `CSE_VERTRAUTE_URSPRUENGE` | نادراً | نطاقاتك، مفصولة بفواصل | يُسمح بنطاقك فقط |
| `CSE_KANONISCHE_BASIS` | للإنتاج | عنوان موقعك | الروابط الخارجة تحمل عنواناً خاطئاً |
| `CSE_CODE_VERSION` | لا | على Vercel تلقائي | حقل في وثيقة GoBD يبقى فارغاً |
| `TEST_DATABASE_URL` | للاختبارات | تُنشئها الاختبارات بنفسها | لا شيء — الاختبارات تدبّر أمرها |

**ما ليس له متغيّر أصلاً** — لأنه ينتظر **قراراً** لا مفتاحاً: البريد
الإلكتروني (O-36)، SMS (O-82)، قراءة الإيصالات (O-135)، الخرائط (O-132)،
n8n (O-123)، LinkedIn وInstagram. وDATEV عمداً بلا ربط: المحاسب يستلم
**ملفاً** (D-06).
