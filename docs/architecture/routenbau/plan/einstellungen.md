# PLAN einstellungen
## Gemeinsames
Alle sechs Routen sind gleich weit: KEINE hat eine eigene page.tsx. Sie laufen heute in die Auffangroute src/app/portal/[mandant]/[...rest]/page.tsx -> MandantUnterseite -> NochNichtGebaut. Das Tor steht bereits: routen.generiert.ts Z. 352, 361, 362, 363, 368, 369 fuehren alle sechs mit Bewachung, Scope M1 und Phase; am Register ist nichts zu aendern, eine neue page.tsx nimmt die Route der Auffangroute einfach ab. Alle fuenf Rechte (system.identitaet_verwalten, stammdaten.verwalten, agent.richtlinie_verwalten, system.einstellung_verwalten, system.audit_exportieren) stehen im Berechtigungskatalog der lebenden Datenbank, alle mit erfordert_2fa = false.

EINE HUELLE fuer alle sechs, kuerzestes vollstaendiges Vorbild ist src/app/portal/[mandant]/einstellungen/dpa/page.tsx: export const dynamic = 'force-dynamic'; const tor = await mandantTor(pfad, mandant); if (tor.art !== 'ok') return <MandantAntwort tor={tor} />; dann PortalRahmen mit wurzelTitel="Einstellungen", aktiverTab="mehr", zugang.leiste, zugang.sichtbareTabs, zugang.navigationsRechte. Gelesen wird in db().begin(SCHNAPPSCHUSS, ...) mit withTenant — nie direkt, nie ausserhalb der gebundenen Transaktion.

EIN SCHREIBWEG fuer alle: in diesem Repository gibt es KEINE Server Actions (die Suche nach _actions.ts trifft nichts). Jedes Formular POSTet auf einen Route-Handler unter src/app/api/einstellungen/<name>/route.ts; einziges vorhandenes Beispiel ist mahnwesen/route.ts mit istGleicherUrsprung -> aktuelleSitzung -> withTenant -> authorize -> Dienst -> 303-Redirect mit ?hinweis=. Jede neue API-Route braucht zusaetzlich eine Zeile in src/server/auth/route-manifest.ts, sonst faellt sie durch die Aufzaehlungspruefung.

EINE STELLE, DIE SIE SICHTBAR MACHT: src/app/portal/[mandant]/einstellungen/page.tsx fuehrt 13 KARTEN, und keine der sechs steht darin. Wer eine Seite baut und die Karte vergisst, baut eine Seite, die nur ueber die Adresszeile erreichbar ist.

EINE MIGRATION traegt drei der sechs: mandant_identitaet (01-KERN.md §6.2, vollstaendig spezifiziert, in keiner der 160 drizzle-Migrationen angelegt) ist die Grundlage von /identitaet UND liefert die Fusszeilen und den E-Mail-Absender fuer /vorlagen; sie lohnt sich also einmal fuer zwei Routen. /arbeitszeit braucht eine eigene (arbeitszeitmodell + tarifvereinbarung), /import eine dritte (migration_lauf + migration_zeile), letztere erst nach O-128. Jede neue Tabelle braucht das K-03-Policypaar, einen Eintrag im RLS-Register in src/server/db/schema/rls.ts und, wo Beweiswert dranhaengt, eine Zeile im KEIN_HARD_DELETE-Register.

ZWEI BEFUNDE, die vor dem Bauen zu entscheiden sind und die beide still scheitern wuerden: (a) die RLS-Policies auf agent_richtlinie pruefen versand.lesen/versand.freigeben, waehrend die Route agent.richtlinie_verwalten verlangt — Tor offen, Datenbank leer; (b) die Tabelle mandant hat ueberhaupt keine UPDATE-Policy, und cse_app haelt auf audit_log kein SELECT auf vorher/nachher. Beide Faelle sehen in der Oberflaeche aus wie 'keine Daten', nicht wie 'kein Recht'.

EINE DOPPELUNG: /portal/[mandant]/einstellungen/agent-richtlinien und /portal/[mandant]/agenten/richtlinien(+/[id]) fuehren dieselbe Bewachung, dieselbe Tabelle und dieselbe SPEC-Nummer (AGT-03, APR-01). Eine der beiden muss die Seite sein, die andere eine Weiterleitung — sonst stehen zwei Editoren auf einer Tabelle.

DIE REIHENFOLGE, die ich vorschlage: zuerst agent-richtlinien und protokoll/export (Tabellen da, Dienstmuster da), dann vorlagen und import (ehrliche Zustandsseiten, kleine Migration bzw. keine), dann die mandant_identitaet-Migration mit /identitaet und dem Schreibteil von /vorlagen, zuletzt /arbeitszeit — die haengt an O-18 und O-50 und ist ohne Antwort nicht redlich zu bauen.

Vorher/Nachher kommen erst in den Export, wenn die Migration das Spaltenrecht oder die Definer-Funktion liefert; bis dahin nennt die Seite die redigierte Fassung redigiert und sagt warum, statt ein Buendel auszuliefern, das aussieht, als sei nichts geaendert worden. Die fehlende audit_kette wird im Manifest benannt: signiert ist das Manifest, nicht eine Kette — ehrlicher als ein Wort 'revisionssicher' ohne Deckung.
